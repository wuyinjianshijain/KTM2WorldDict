# 魔法与法术系统

> **实装状态**：建设中 · **核对**：与 IsekaiExpansion 游戏数据逐项核对 · **密度目标**：每系 6 项核心法术，合计 72 项（当前无一系达标）· 全部待办见[待完成池](Pending_Pool.md)

## 1. 玩家承诺与范围

法系是魔法的**内容层**：十二个法系各自应当提供一种改变战场的语言，而不只是十二种颜色的伤害。

这一层的骨架已经完成——十四种法强、三级共鸣阶梯、法系状态与星界能量资源全部实装并生效，详见[属性、天赋与状态系统](Attribute_and_Status_System.md)。**缺的是内容**：目前只有 24 个法术，其中火系独占 7 个，水系与光系一个都没有。因此本文件的状态是**建设中**，它记录已经存在的法术与已经确认的缺口，不为尚未存在的法术预留设定。

## 2. 世界内解释

术式是施术者、魔导体、环境精魂与目标共同完成的一次法则协商。时钟塔把常见的协商方式整理成可教学的分类，公会再用这套分类登记导师与委托；民间仍会把同一术式叫成不同名字。分类服务于教学与实现，不代表自然界真的存在互不往来的“元素盒子”。

完整的世界内原理、六元素与高阶学科的文化解释见[魔法系统背景](../Lore/Magic_System_Lore.md)。

## 3. 施法资格

魔法是三类适性中唯一采用**硬门槛**而非数值惩罚的：

| 条件 | 结果 |
| --- | --- |
| 持有「星能调律」（魔法师、神官、牧师） | 可通过常规施法媒介施法 |
| 未持有 | **完全无法**通过常规媒介施法，客户端以红色行动栏文本提示，不静默失败 |
| 未持有，但使用魔法卷轴 | 可以施放，卷轴自带能量倍率 |
| 创造模式 | 不受限制 |

近战与远程走“能用但很弱”（伤害减半），魔法走“直接不可用”，因为半吊子施法在体验上比无法施法更糟。魔法卷轴是刻意保留的应急通道，让非施法职业仍然能在解谜与突发状况中使用少量术式。

## 4. 星界能量

法术消耗星界能量而非独立法力条。消耗值登记在 `spell_energy` 表中，与法术定义分离，因此调整消耗不需要改动法术本身。

已登记消耗跨度为 1 至 100：入门法术在 5—20 区间，终结型法术「天坠」为 100，是全表最高。**「炎陨」登记为 1**，与同级法术相差一个数量级，属于待确认项。

| 光 | 0 | **未完成** | 有法强、有「光耀」状态、有羽灵族联动 |

**水系与光系是全系统最明确的内容缺口。** 两个种族的招牌能力——鱼人族「镜水结界」与羽灵族「神代余音」——都建立在这两系的法强之上，但玩家拿不到任何一个对应法术，只能靠装备被动堆法强。这是唯一一处**种族设计已完成、法系内容却完全缺席**的组合。

星界系的两个法术都是传送工具，没有任何战斗法术；治疗系没有群体治疗，而神官是专职远程治疗职业。这两项在优先级上仅次于水系与光系。

## 7. 密度目标

**设计裁决：十二法系拉平法术密度。** 目标是每系 **6 项核心法术，全系合计 72 项**。

拉平的对象是**核心法术**，不是法术总数。每系的六个核心位各有固定职责，这既保证每个法系都能独立成军，也防止清单重新膨胀成上一版的百项规模：

| 核心位 | 职责 |
| --- | --- |
| 入门单体 | 低消耗、可长期使用的基础输出 |
| 范围或多发 | 清场与压制 |
| 状态或控制 | 施加本系的标志性状态 |
| 防御、位移或支援 | 让该系单独存在时也能自保 |
| 终结 | 高消耗、高回报的兑现手段 |
| 工具 | 探索、侦察或场景交互 |

**不占核心配额的两类法术**：角色专属变体（如「焰之」系列）与跨系法术（如灵魂属性的「灵魂火弹」「魂火召唤」）。按此口径重算，火系的核心法术是 3 项而非 7 项——**没有任何法系已经达标**，火系只是变体最多。

| 法系 | 核心法术 | 距 6 项缺口 |
| --- | ---: | ---: |
| 火 | 3 | 3 |
| 奥秘 | 3 | 3 |
| 灵魂 | 3 | 3 |
| 冰 | 2 | 4 |
| 雷 | 2 | 4 |
| 治疗 | 2 | 4 |
| 星界 | 2 | 4 |
| 风 | 1 | 5 |
| 土 | 1 | 5 |
| 暗 | 1 | 5 |
| 水 | 0 | 6 |
| 光 | 0 | 6 |

补完顺序按缺口大小与系统依赖决定：水与光最先（两个种族的招牌能力依赖它们且完全无内容），随后是暗、土、风，最后补齐已有基础的六系。

## 9. 权威边界

`spellsreference_paladins` 与 `spellsrefernece_wizards` 两个命名空间是外部参考包（Spell Engine 的圣骑士与法师示例内容），**不属于本作内容**，不得作为法术清单来源，也不得在设定文档中引用其法术名。本文件第 5 节是本作法术的完整清单。

## 10. UI、程序与本地化

- 法术描述使用占位符 `{ise_damage}`、`{ise_duration}`、`{ise_radius}`、`{ise_count}`、`{ise_heal}`、`{ise_secondary_damage}` 由运行时填充，翻译时不得改写占位符名称。
- 法术描述先写结果，再写条件与代价。
- 星界能量消耗登记在独立数据表中，新增法术必须同批登记消耗，否则该法术将不消耗资源。
- 地面危险与法术落点需要统一的轮廓语言，当前尚无实装规范，见[待完成池](Pending_Pool.md)。
