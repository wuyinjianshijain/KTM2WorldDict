# 《KTM2》WorldDict

> **一句话世界定位**  
> 厄达斯曾被一位坠落的女神拯救过一次；千年后的今日，人们才逐渐发现，这份安稳一直在拿“尚未发生的未来”偿债。

WorldDict 是《KTM2》的**世界设定库**：背景故事、世界观与可供取用的创作素材。它既记录玩家能够在旅途中感受到的生活，也保存剧情需要的隐藏因果。这里的内容以“能进入游戏”为标准：一项设定必须留下地貌、制度、物价、习惯、冲突或角色选择中的至少一种痕迹。

**它不是游戏内 Wiki。** 本仓库不登记数值、资源键、技能节点、法术清单与实装进度——那些属于[游戏内文档](https://kentomahou.com/)，并以那里为准。本仓库服务三类读者：写剧情、同人与任务的开发者；需要了解这个世界的玩家；以及为它补充设定的投稿者。

## 1. 玩家承诺

玩家以没有被厄达斯法则登记的“异乡人”身份醒来。最初的目标很小：在边境镇找到一张床、一份工作，以及愿意相信自己的人。随着旅程延伸，玩家会发现地下城并非凭空出现的迷宫，而是被世界舍弃的历史和未来；所谓拯救，也不再是击败唯一的恶，而是在“延续眼前的和平”与“把选择权还给后来者”之间寻找第三条路。

世界的主要体验由四根支柱组成：

- **可以住下来的冒险世界**：聚落拥有工作、房租、饮食、交通、治安和会随剧情改变的熟人。
- **立场先于善恶**：帝国、教廷、魔族、精灵与魔法学者都在保护某些人，也都让另一些人承担代价。
- **魔法是生活基础设施**：魔导体、星塔和魔石既能发动奇迹，也会影响矿业、医疗、战争与阶级。
- **队友拥有不随主角消失的人生**：同行者有职责、旧债和自己的选择；亲密关系改变他们面对问题的方式，而不是替他们解决问题。

## 2. 当前核心事实

1. **厄达斯不是被神创造的世界。** 被后世称为“神族”的星律民是来自界外的高位文明，亚斯特拉・瑟怜只是其中的守望者之一。
2. **遥空庭院、世界熔炉与星塔网共同维持现世。** 它们延缓了神代灾变，却会持续消耗未实现的可能性。
3. **破碎空间是被切离现实的可能世界。** 地下城中的“过去”和“未来”可能从未发生，却能带回真实的伤口、物资与证据。
4. **魔族是神代战争的替罪者。** 他们的远祖早于现存人类国家抵达厄达斯；战后史书把复杂的联盟与背叛改写成了便于统治的正邪故事。
5. **异乡人不是被召来充当更强的武器。** 只有未被本世界因果登记的观察者，才能进入不同可能性并作出不会立刻被世界熔炉抹平的选择。

## 4. 建议阅读顺序

玩家向资料以本页、地点总览和核心人物为起点。剧情与任务设计继续阅读世界历史、阵营独立词条和角色的“信息分层”。需要具体数值、技能节点或法术清单时，直接查[游戏内文档](https://kentomahou.com/)，不要在本仓库里找。

涉及核心真相的段落会明确标注“**核心剧透**”。公开图鉴、商店文本和初见台词不得直接引用这些内容。

### 关联仓库与权威方向

| 仓库 | 地址 | 它负责什么 |
| --- | --- | --- |
| WorldDict（本仓库） | <https://github.com/Kzeroko/KTM2WorldDict> | 世界设定、背景故事与创作素材 |
| 游戏内文档 | <https://kentomahou.com/> · <https://github.com/Kzeroko/kzeroko.github.io> | **游戏内一切内容的唯一权威**：属性、天赋、法术、术式、技能树、状态、物价与实装进度 |
| IsekaiExpansion | <https://github.com/Kzeroko/IsekaiExpansion> | 游戏实装本体与数据 |

权威方向是不对称的，写内容前务必分清：

- **游戏内事实以游戏内文档为准。** 数值、等级、倍率、节点、法术名单、资源键与「某项内容是否已实装」都在那边；本仓库只描述这些东西在世界内的样子、称呼与后果，不复制它们的表格，也不代替它们宣布实装状态。两边冲突时，以游戏内文档为正。
- **世界内事实以本仓库为准。** 历史、制度、人物、动机、文化与因果链在这里裁决。
- **经济的世界内基准在本仓库**（[货币、工价与生计](Lore/Economy_and_Livelihood.md)：工价、生活成本与价格因果）；**经济平衡的数值契约不在这里**，由 `jrpg-design` 技能的 `references/economy-and-progression.md` 维护。
- **不写进本仓库的东西**：数值表与公式、资源键与注册 ID、技能树节点、实装进度与排期、美术 / 音频 / 关卡制作指令、以及任何尚未实际存在的任务与状态流程。详见[编写规范](AUTHORING_GUIDE.md)第 2 节。

工具链默认三个仓库**并列检出**，因此可以互相按 `../` 定位。不要在任何文档或脚本里写死本机绝对路径。

## 6. 参与贡献

**如果有想法，可以向我这里提交。** 这边支持提交自己想出来的设定和角色，提交后合理的部分可以合并到本体，一起把它做成一部社区驱动的世界辞典。

| 你手上有的 | 怎么做 | 需要会 Git 吗 |
| --- | --- | --- |
| 一个设定点子、一个角色雏形 | 开 Issue，选「设定提交」或「角色提交」 | 不需要 |
| 已经写好的词条 | Fork 后开分支，提 Pull Request | 需要 |
| 发现矛盾、错误、失效链接 | 开 Issue，选「问题反馈」 | 不需要 |

采纳标准只有一条：**它能进入游戏。** 一项设定至少要在地貌、制度、物价、习惯、冲突、任务或角色选择里留下一种痕迹；说得出谁获益、谁付出代价的设定，比写得漂亮的设定更容易被合并。

社区提交的内容合并时一般先标记为 `draft`，等到被剧情或系统实际采用后再转为 `canon`。完整流程、词条模板与授权条款见[参与贡献指南](CONTRIBUTING.md)，写法要求见[编写规范](AUTHORING_GUIDE.md)，社区约定见[行为准则](CODE_OF_CONDUCT.md)。
